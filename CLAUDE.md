# Правила: фронтенд

Общий регламент работы — в `CLAUDE.md` родительской папки. Здесь только то,
что специфично для этого проекта.

## Топология — не обсуждается

Браузер ходит **только** в `/api/graphql` этого приложения. Прямой запрос
из клиентского кода в бэкенд запрещён: он раскрывает адрес, ломает identity
(её ставит сервер) и требует CORS.

Любой новый способ получить данные проходит через `src/lib/graphql/execute.ts`.
Второй путь в бэкенд — это второй набор проверок, который разъедется с первым.

## Новая операция — три шага

1. Добавить документ в `src/lib/graphql/operations.ts` — **через `graphql()`,
   не `gql`**: только так документ типизирован. Не добавил — операция
   не работает вовсе: allowlist её отвергнет.
2. `pnpm codegen` при поднятом бэкенде.
3. Использовать в компоненте. Дженерик у `useQuery` не пишем — тип выводится
   из документа.

Типы **не пишутся руками**. Рукописный интерфейс — это утверждение, а не
проверка: в этом проекте он врал про `status` (enum, а не строка) и про
`providerRef` (необязательный). Строка таблицы берётся как
`OrdersListQuery["orders"]["items"][number]`.

Сгенерированное коммитим, руками не правим. Забыл перегенерировать — типы
уверенно врут, и это хуже, чем их отсутствие. В CI — `pnpm codegen:check`.

## Клиентские компоненты

`"use client"` ставится там, где реально нужны состояние, эффекты или
обработчики. По умолчанию компонент серверный: он не отправляет JS в браузер.
`ApolloProvider` оборачивает только поддерево, которому нужны данные.

## Секреты

Ни один секрет не попадает в бандл. Всё, что не `NEXT_PUBLIC_`, доступно
только на сервере; файлы с секретами импортируют `server-only`, чтобы случайный
импорт из клиентского компонента падал на сборке, а не утекал в браузер.
